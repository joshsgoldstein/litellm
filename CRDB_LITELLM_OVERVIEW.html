Open-source integration

CockroachDB × LiteLLM

Making CockroachDB a first-class option inside LiteLLM, the open-source AI gateway, across three independent contributions.

Project overview · contributed upstream to BerriAI/LiteLLM

Context

LiteLLM is a widely used open-source LLM gateway. Teams put it in front of many model providers (OpenAI, Anthropic, Bedrock, Vertex, local models) to get one API, one set of keys, and central spend tracking, budgets, and rate limits. Its proxy keeps all of that operational state in a SQL database, which today is Postgres only.

We are making CockroachDB work with LiteLLM in three independent ways. They are separate pieces of work and separate contributions; none depends on the others.

The three additions

1

CockroachDB as the backing database

The "spine", the store that holds keys, teams, users, budgets, and spend.

WhatLet LiteLLM's proxy run its operational store on CockroachDB in place of Postgres.
WhyThis is the substantial one. It lets an organization run LiteLLM on CockroachDB and get CRDB's resilience, scale, and multi-region behavior for their AI gateway's control plane.
HowLiteLLM reaches its database through Prisma, and most of its schema and queries are already portable. A small number of Postgres-only constructs were not. We replaced five of them with standard equivalents that behave identically on Postgres, so this is portability work, not a CockroachDB-specific fork: a worker-heartbeat time calculation moved to standard SQL, a key-hashing step moved from SQL into application code, and three uses of Postgres advisory locks were replaced with standard row-level locking.
StatusDevelopment complete · validation in progress
Code complete, all lint and type checks pass, unit tests pass, and an end-to-end smoke test succeeds on CockroachDB (proxy boot, key creation, real model completions, spend tracking, team management). Full validation, concurrency and isolation behavior under load, is underway with the integration team and is not yet complete.
IsolationRuns on CockroachDB's default (SERIALIZABLE); no configuration change required.
Branchlitellm_crdb_backend
2

CockroachDB in the connector list

A first-class, recognizable option in the gateway's UI.

WhatAdd CockroachDB to the list of well-known connectors LiteLLM shows when registering an MCP (Model Context Protocol) server.
WhyDiscoverability and first-class presence, placing CockroachDB alongside the other recognized names users already see.
HowA small, backend-agnostic UI addition. It has nothing to do with which database LiteLLM itself runs on.
StatusPlanned
3

CockroachDB as a vector store

Native vector search, usable through the same gateway.

WhatAdd CockroachDB as a supported vector-store provider, using CockroachDB's native vector search for retrieval (RAG).
WhyIt lets people use CockroachDB's vector capabilities through the same LiteLLM gateway they already use for model calls.
HowA vector-store provider following LiteLLM's existing plugin pattern, connecting with its own credentials.
StatusScoped · one design decision open
Deliberately decoupled from addition 1. Someone can run LiteLLM on Postgres (or anything) as its spine and still use CockroachDB purely as a vector store. The vector store connects with its own credentials and never touches the proxy's main database connection.

How they fit together

They are independent. Each ships as its own pull request to the LiteLLM open-source project, so they can be reviewed and merged on their own timelines. Addition 1 is the substantial one; additions 2 and 3 are smaller and self-contained. Keeping them separate also means the vector store (3) never implies you must run CockroachDB as your spine (1).

Contribution approach

We are contributing these upstream to the LiteLLM project rather than maintaining a private fork, so the work lands in the product everyone uses. That means following the project's contribution rules: one focused change per pull request, tests, passing the full lint and type gates, and real end-to-end proof of each change. A corporate Contributor License Agreement is in progress, which is the one legal prerequisite before anything can merge.
